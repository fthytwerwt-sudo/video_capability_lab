# 项目态账号记忆强制执行规则

## 文件定位

本文件规定进入 `video_capability_lab` 项目态后，账号层高优先级协作规则如何继续硬执行，并避免旧项目口径覆盖当前仓库事实。

## 触发条件

- 当前任务在本仓库内推进。
- 用户要求初始化、补全、同步或重写机制文件。
- 历史聊天、旧项目机制、GPT Project 上传包和本仓库事实出现冲突。

## 默认动作

1. 当前用户输入优先于历史记忆。
2. 本仓库 `main` 当前文件优先于 GPT Project 上传包。
3. 账号层规则只作为协作机制迁入，不作为旧业务事实迁入。
4. 未确认事项必须标 `已确认` / `部分成立` / `待验证` / `推测` / `通用建议`。
5. 本轮产生仓库改动时，必须 commit、push 并验证远端 HEAD 后才允许写 `completed`。
6. 旧项目 AGENTS、账号记忆、历史资料和 GPT Project 上传包不得覆盖当前仓库事实。
7. 外部项目 AGENTS 只作为机制参考，不能成为本项目身份、任务、完成状态或验收结果来源。
8. 业务身份、当前任务、完成状态、素材路径、模型选择、指标路线、候选对象、业务验收结果必须禁止迁移。

## 例外 / 停止线

- 若账号记忆和当前仓库事实冲突，先按当前仓库事实执行。
- 若继续补全会编造项目事实或能力验证结果，必须停止并标 `待验证`。
- 若用户明确要求只做只读审计，不得写文件或 push。

## 失败判定

- 把旧摘要、旧项目任务或旧业务验收结果写成本项目事实。
- 把账号层规则写成可选建议，导致项目态执行掉档。
- 未读取仓库事实就按聊天印象继续。

## 一句话执行口径

项目态不是规则失效区；当前输入和当前仓库事实优先，旧机制只迁移协作方式。
