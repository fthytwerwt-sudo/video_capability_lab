# 真实意图澄清闸门机制

## 文件定位

本文件规定当用户提出方向型、能力型、demo 型、项目生死判断型或 Codex 执行型任务时，GPT 必须先澄清真实目标、验收标准和失败判定，再决定是否下发 Codex。

## 触发条件

- 用户说“让 Codex 做一下 / 给我 Codex prompt / 直接执行”。
- 用户提出 demo、probe、能力验证、最小闭环、项目是否成立、能不能做出来。
- 用户输入里同时出现方向判断和执行请求。
- 用户的真实目标可能不是“完成一个任务”，而是判断项目是否值得继续。
- 用户表达“别抽卡 / 别浪费时间 / 我需要知道能不能成立 / 做不出来项目就失败”。
- 任务会影响项目主线、工具选型、机制设计或继续投入。

## 默认动作

1. GPT 先判断用户真实目标属于哪一类：
   - 能力是否成立
   - demo 是否像样
   - 项目是否值得继续
   - 工具链是否够
   - 机制是否缺失
   - 是否只是执行已确认任务

2. GPT 必须先补齐：
   - 本轮真正要判断什么
   - 目标
   - 边界
   - 输入
   - 输出
   - 验收标准
   - 失败判定
   - 继续 / 停止条件

3. 如果真实目标不清楚，GPT 不能直接下发 Codex，而应：
   - 先和用户聊清楚；或
   - 给出一个“默认假设 + 待确认位 + 可执行版本”；并明确说明假设。

4. 如果用户明确说“这轮只执行，别判断”，可以收缩澄清，但仍必须检查：
   - 是否会破坏仓库边界
   - 是否会把待验证写成已确认
   - 是否会提交不该提交的素材或运行产物
   - 是否会迁移旧项目业务事实

5. 只有以下条件满足，GPT 才能输出 Codex 执行单：
   - 本轮目标清楚
   - 边界清楚
   - 验收清楚
   - 失败判定清楚
   - 是否需要 commit / push 清楚
   - 是否允许生成视频 / 安装依赖 / 调用 API 清楚

## 输出要求

若进入 Codex 执行单，必须在 Context 或 Constraints 中显式写入：

- 用户真实目标
- 本轮不是在验证什么
- 成功标准
- 失败标准
- 停止条件
- 是否只是能力证明，不是最小闭环
- 是否只是工具链检测，不是能力成立

## 例外 / 停止线

- 简单事实问答不触发。
- 明确单点改字、改格式、只读查看可轻触发。
- 用户明确只要一个小执行任务时，可以不展开长澄清，但不得丢失安全边界。
- 若继续澄清会拖慢紧急修复，可先按保守默认假设执行，但必须标明假设和可回滚。

## 失败判定

- 用户想判断项目是否成立，GPT 却只给单组件玩具 probe。
- 用户想判断工具链能不能成品化，GPT 却只让 Codex 写说明文档。
- 用户真实目标没清楚，就直接输出 Codex prompt。
- 把 demo 做出来写成项目闭环成立。
- 把工具安装成功写成能力验证成功。
- 把参考视频解析写成 Remotion 能力已成立。

## 一句话执行口径

先聊清真实目标，再下发执行；不清楚目标的 Codex prompt，就是把项目拿去抽卡。

## 正片意图默认完整交付规则

用户说“正片 / 成片 / 发布候选 / 最终视频 / 直接出片 / 我只想看正片”时，默认真实意图是发布候选完整体验，而不是局部模块测试。

这种场景默认不需要追问“要不要贴纸 / 要不要字幕 / 要不要动效 / 要不要审片包”。除非用户明确说不要，否则这些项目已确认重要模块默认包含。

只有出现以下情况，才需要阻断或回问：

1. 必需模块缺少输入。
2. 必需模块当前能力缺失。
3. 模块之间存在明确冲突，例如贴纸遮挡主体或字幕冲突。
4. 执行完整正片会违反本轮禁止项，例如本轮禁止 render、禁止 API 或禁止 Remotion。
5. GPT 准备删除某个默认模块，但没有用户明确确认。

如果 GPT 准备删贴纸、字幕、动效、审片包或失败回路，必须先得到用户明确确认；不能用“prompt 没写”或“我判断不需要”替用户决定。

Codex 收到正片类执行单时，如果 prompt 缺完整模块清单，必须按 `51_正片候选完整交付闸门_full_video_candidate_delivery_gate.md` 补齐检查；若缺项无法补齐，必须 blocked。
