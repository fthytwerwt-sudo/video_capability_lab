# P0-P1-P2 锚点与抗漂移机制

## 文件定位

本文件规定本项目判断优先级，防止任务被旧项目、旧摘要、能力幻想或聊天漂移带偏。

## 触发条件

- 多文件初始化或重写。
- 项目事实、机制文件、GPT Project 上传包之间存在冲突。
- 需要判断能力是否成立、是否能进入 probe、是否能写完成。
- 执行过程出现 blocker 或路线失败。

## 默认动作

1. `P0`：用户本轮明确目标、边界、禁止项、完成标准。
2. `P1`：本仓库当前文件、验证结果、commit / push / remote HEAD 事实。
3. `P2`：源项目机制、历史记忆、浏览器规划、旧项目摘要。
4. 冲突时按 `P0 > P1 > P2` 执行。
5. `P1` 证据不足时写 `待验证`，不得用 `P2` 冒充当前事实。
6. 外部项目 AGENTS 属于 `P2` 机制参考层，只能提供待抽象机制，不得提升为当前项目事实。
7. 旧项目归档资料、历史过渡口径和外部项目 AGENTS 不得高于当前用户输入和当前仓库事实。

## 例外 / 停止线

- 用户临时要求探索方案时，可以写 `推测` 或 `通用建议`，但不能写成本项目事实。
- 只有通过脚本、测试、人工复审或远端 readback 的内容，才能升级成 `已确认`。

## 失败判定

- 用历史路线判断覆盖本轮硬约束。
- 把 capability 规划写成 capability 已验证。
- 把 local-only 文件写成 remote 完成。

## 一句话执行口径

先锁本轮目标，再守仓库事实，最后参考旧机制；一旦漂移，立即回拉到 `P0 / P1`。
