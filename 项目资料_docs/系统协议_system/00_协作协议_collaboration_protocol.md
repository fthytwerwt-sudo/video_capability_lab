# 协作协议

## 文件定位

本文件规定 `video_capability_lab` 的三层协作方式：`GPT Project` 是配合机制层，`GitHub 仓库` 是项目事实层，`Codex` 是执行落库层。

本文件只承载协作方式、判断顺序、同步规则和执行边界，不承载项目事实结论。

## 触发条件

- GPT / Codex 进入本仓库接手任务。
- 用户要求同步 GPT Project 上传包。
- 任务涉及机制、执行边界、状态判断、验收口径或 push 规则。
- 新增或修改系统机制文件、项目事实文件、执行桥接文件。

## 默认动作

1. 先读 `AGENTS.md`，再按默认读取顺序读取系统协议和项目事实文件。
2. 把当前用户输入作为 `P0`，把本仓库当前文件作为 `P1`，把旧项目机制和历史聊天作为 `P2`。
3. GPT 负责目标、边界、实现设计、验收和复审判断；Codex 负责按已锁定实现设计落库、脚本、验证、commit、push 和远端 HEAD 验证。
4. GPT Project 上传包只同步系统机制，不同步 `AGENTS.md`、执行日志或项目事实。
5. 任何能力、样片、组件、管线在 probe 通过前都写 `待验证`。
6. 方向型、能力型、demo 型、项目生死判断型任务必须先过真实意图澄清闸门：GPT 先澄清真实目标、成功标准、失败标准和停止条件，再下发 Codex。
7. Codex 不负责在执行中自行决定核心实现路线；缺实现设计层时必须 `blocked_need_implementation_design_layer` 或回报缺口。

## 外部项目 AGENTS 机制参考边界

- 外部项目 AGENTS 只能只读审计，不能作为当前项目事实源。
- 外部项目 AGENTS 只作为机制参考；可迁移内容必须先抽象成协作机制。
- 只迁移协作机制，不迁移业务事实。
- 业务身份、当前任务、完成状态、素材路径、模型选择、指标路线、候选对象、业务验收结果必须禁止迁移。
- 借鉴外部机制后，必须同步当前项目 `AGENTS.md`、`codex_source/01_execution_rules.md`、检查标准和 latest；若属于长期机制，还必须先写入 `项目资料_docs/系统协议_system/` 再同步 GPT Project 上传包。

## 例外 / 停止线

- 若用户本轮明确覆盖某条默认规则，以用户本轮输入为准。
- 若执行会调用外部 API、生成视频、安装大型依赖或迁移旧项目业务事实，必须停止并按当前任务边界重判。
- 若缺少源机制文件或仓库身份无法确认，必须 `blocked`。

## 失败判定

- 把 GPT Project 上传包当项目事实源。
- 把旧直播、电商或视频工厂业务结论迁入本项目。
- 把 `待验证` capability 写成已成立。
- 本地改完但未 commit / push / remote HEAD 验证就写 `completed`。

## 一句话执行口径

GPT 定方向、实现设计和验收，GitHub 存事实，Codex 按已锁定实现设计负责可执行落库和远端闭环；机制可迁移，旧业务事实不迁移。
