# 原感稿锁定与双层并存机制

## 文件定位

本文件规定用户提供原感稿、风格描述、参考文案、镜头感觉或视频观感时，如何同时保留原感参考层和执行桥接层。

## 触发条件

- 用户说“保留这个感觉”“odd / apple glass / vlog 这种味道”“别改掉原感”。
- 需要把参考表达转成组件、时间轴、动效、BGM 或验收标准。
- 同一份材料既要保留气质，又要变成可执行文件。

## 默认动作

1. `原感参考层` 保留用户原意、语气、氛围、节奏偏好。
2. `执行桥接层` 把原感拆成组件、输入、输出、约束、验收和禁止项。
3. 两层并存，互不覆盖。
4. 写入 GPT Project 上传包时只同步通用机制；具体原感和项目事实留在仓库项目事实文件。

## 例外 / 停止线

- 用户明确要求直接改写原稿时，可改写，但需标明原稿已被替换。
- 参考涉及第三方品牌或平台 UI 时，保留机制，不复刻资产。
- 原感不足以执行时，必须补字段或标 `待验证`。

## 失败判定

- 用执行稿覆盖原感，导致参考气质丢失。
- 把原感直接当执行规则，缺少字段和验收。
- 把第三方可识别资产写成可迁移组件。

## 一句话执行口径

原感锁住，执行另起一层；参考保气质，落地靠字段、组件和验收。
